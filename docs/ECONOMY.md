# Экономика — Help Desk Idle

Источник формул: Anthony Pecorella, *The Math of Idle Games*
— Part I: https://www.gamedeveloper.com/design/the-math-of-idle-games-part-i
— Part III: https://www.gamedeveloper.com/design/the-math-of-idle-games-part-iii
Параметры — по образцу AdVenture Capitalist, расширены до 12 работ. **Таблицы — черновик**; финальный баланс подбираем симуляцией (`tools/sim`, позже). Все числа живут в JSON.

## Обозначения
`b` — baseCost, `r` — growth rate, `k` — текущий уровень, `n` — сколько покупаем, `c` — деньги.

## Формулы (Part I)
- Цена следующего уровня: `cost_next = b' · r^k`, где `b' = b · Π(1 − discount)` (скидки менеджеров за TechCoin)
- Цена n уровней: `cost(n) = b' · r^k · (r^n − 1) / (r − 1)`
- Максимум к покупке: `max = floor( log( c·(r−1) / (b'·r^k) + 1 ) / log(r) )`
- Выплата за цикл: `payout = revenue · k · M_job · M_global · (1 + coins · coinBonus)`
- Длительность цикла: `cycle = time / S_job / S_global`
- Доход/сек (UI, оффлайн): `payout / cycle`

## Открытие работ

## Повышения на порогах (этап 2a)
- Уровень работы упирается в её следующий порог (25, 50, 100, 200, …) — «потолок». Дальше — **повышение** за
  `promotionCost = promotionFactor · bulkCost(baseCost, growthRate, rank, cap − rank)` — ×2 пройденного отрезка уровней
  (`promotionFactor = 2`, `config.json`). Соразмерно кривой цен каждой работы: «мышка» на пороге 25 — 25,5 тыс., а не 14 млн,
  как было при «50 следующих уровнях» (у работ с ростом 1,15 это улетало в небо).
- Оплата → ранг работы = порог, открывается следующий отрезок уровней, начисляется награда порога.
- **Награды порогов считаются по рангу**; глобальные — по минимальному рангу всех 12 работ.
- **На пороге менеджер ждёт повышения:** авто-сбор и оффлайн-доход работы стоят, ручные тапы работают.
- **Пороги после 500:** каждые 100 до 1000, дальше каждые 250, чередуя «скорость ×2» и «прибыль ×3/×4» — у каждой работы столько
  порогов скорости, чтобы со своими + глобальными 25/50 цикл стал < 0,25 с («поток», `fastCycleThreshold = 0.25`):
  работы 1–9 — до ур. 1250, 10 — 2250, 11 — 3250, 12 — 4750.

## Достижения (пороги уровней)
По образцу AdCap: каждая работа на 25, 50, 100, 200, 300, 400 → скорость ×2; на всех остальных кратных 25 (75, 125, 150, …) — **прибыль ×1,5** (порог = повышение каждые 25 уровней, см. `docs/BALANCE_MODEL.md`); дальше каждые 100 до 1000, потом каждые 250 — чередование «скорость ×2» и «прибыль ×N» (×3…×4). Глобальные: «все работы ≥ 25/50/100/…» → скорость ×2 всем.
Список порогов и эффектов — `milestones.json`: `{ jobId | "all", level, effect: "speed"|"profit", value }`.
Галерея показывает все пороги; ещё не достигнутые следующие — под замком (условие скрыто до уровня предыдущего порога).

## Менеджеры
- **За деньги** (таблица выше): автосбор и автоперезапуск, работа идёт оффлайн. Нанять можно **после второго повышения** работы — ранг ≥ 50 (`config.managerMinRank`). Условие по рангу одинаково для всех работ, в отличие от абсолютного уровня.
- **За TechCoin** (этап 3): скидка на уровни работы (−10%, −99.9% у поздних, как в AdCap), помощь «трудной» работе.

## Улучшения
- **За деньги:** прибыль конкретной работы ×3; «Кофемашина в офисе» — вся прибыль ×3.
- **За TechCoin:** вся прибыль ×3, эффективность TechCoin +2%, +10/+50 уровней работе.

## Оффлайн-доход
`offline = Σ по работам с менеджером ( floor(elapsed / cycle) · payout )`. Работы без менеджера: доводят текущий цикл и встают в `ready` (деньги — после тапа).
`elapsed` ограничен `offlineCapHours` (по умолчанию 24).

## Быстрые циклы
`cycle < 1/30 с` → считаем число завершённых циклов за тик и выплачиваем пачкой; UI — «$X / сек».

## Престиж: «Реорганизация» → TechCoin (этап 3)
Формула AdCap (Part III), от денег за всё время:
- Всего заработано монет: `coinsTotal = floor( 150 · sqrt( lifetimeEarnings / 1e15 ) )`
- Получишь при сбросе: `claim = coinsTotal − coinsEverClaimed`; кнопка активна при `claim ≥ 1`
- Бонус: каждая монета **на счету** = `+coinBonus` к прибыли (2% + рост от грейда, см. ниже). Потраченные монеты бонус не дают — тратить с умом.
- Так как `lifetimeEarnings` копится через все сбросы, каждый следующий сброс выгоден только при большем заработке (удвоение монет ≈ ×4 денег).
- Сброс обнуляет: деньги, уровни, менеджеров за деньги, улучшения за деньги. Сохраняет: TechCoin, всё купленное за TechCoin, `lifetimeEarnings`, достижения в галерее.
### Грейд отдела (рост бонуса за монету)
Бонус за монету не фиксирован: он растёт с **грейдом**, а грейд — с общим числом TechCoin, полученных за все сбросы (`coinsEverClaimed`; траты не уменьшают).
- Порог грейда g (геометрическая прогрессия): `need(g) = gradeBase · gradeStep^(g−1)` → при `gradeBase = 100`, `gradeStep = 4`: 100, 400, 1 600, 6 400, 25 600 …
- Текущий грейд: `grade = max g, при котором coinsEverClaimed ≥ need(g)` (0, пока < 100)
- Бонус за монету: `coinBonus = coinBonusBase + gradeBonusStep · grade + бонусы улучшений` → 2% + 1% за грейд
- Почему не ломает экономику: монеты ~ √деньги, порог ×4 монет ⇒ каждый следующий грейд требует ×16 заработка. Бонус растёт линейно от грейда, т.е. логарифмически от денег.
- UI «Реорганизации»: текущий грейд, бонус за монету, прогресс-бар до следующего грейда («ещё 230 TechCoin до Senior»).

Параметры `coinScale = 1e15`, `coinFactor = 150`, `coinBonusBase = 0.02`, `gradeBase = 100`, `gradeStep = 4`, `gradeBonusStep = 0.01` — в JSON.

## Числа и формат
- `Double` в MVP; при необходимости — свой `BigNumber`.
- Формат: < 1 000 000 — с разделителями; далее `млн / млрд / трлн / квдрлн / квнтлн` (EN: million … quintillion), затем `aa, ab, ac…`.
- Логика — в `Core/Economy`, чистые функции.
